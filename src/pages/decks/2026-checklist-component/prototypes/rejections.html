Rejected options

Everything considered and not taken, with what won instead and why. Each entry links to the bench configured to show the rejected state, so an option can be seen rather than described. This grows as rounds land; it is not a postscript written at the end.

Editing

Rejected

An editor opens as an object

Chosen

contenteditable on the text already there

A bordered field, a persistent toolbar and Save / Cancel announce that you have entered a mode. Editing a list item is not a mode, it is typing. Nothing should be swapped in and nothing should reflow.

Rejected

A hairline around the field

Chosen

No chrome at all. A caret and nothing else

Any resting outline makes every row look operable whether or not you may edit it, and it pulls the eye down a list of otherwise quiet rows. Cut as distracting. See the hairline version

Rejected

border + padding to paint edit state

Chosen

background + box-shadow, outside layout

The obvious implementation moves the glyphs 9px right and 7px down on entry and shoves every row below it by 14px. Painting with background and box-shadow measures 0px. This is the one worth showing live rather than asserting. See the shove

Rejected

A Save button

Chosen

Autosave throughout, Esc to revert

A button promises nothing is written until it is pressed. Inline editing promises the text is the document and that leaving commits. Both cannot be true at once, so one of them had to go.

Rejected

Save on blur

Chosen

Debounced autosave, 4s idle with a 15s ceiling

Not a taste call. Interim keystrokes travel as client events that bypass the server, so anyone arriving mid-edit hydrates from the database and reads stale text for the whole session. Save-on-blur leaves that hole open for as long as someone keeps typing.

Rejected

A pure idle debounce, no ceiling

Chosen

Idle debounce with a hard 15s maxWait

A trailing debounce never fires while someone keeps typing, so drift is unbounded. The ceiling is a correctness requirement, not a refinement. The bench fires it on its own if you type for fifteen seconds without pausing.

Rejected

A flash confirming each save

Chosen

Say nothing

With a row treatment that already lifts when the words settle, a second confirmation is noise. Worth revisiting only because silence currently leaves a failed write with no surface at all, which C5 has to answer. See the confirming version

Ordering

Rejected

Integer positions

Chosen

Fractional index as a sortable string

One move rewrites every row between the old and new slot, so two simultaneous drags overwrite each other wholesale instead of merging. A fractional index writes one row and both intents survive. See the write amplification

Rejected

Float positions

Chosen

Fractional index as a sortable string

Halving the gap between the same two neighbours exhausts the double mantissa after about fifty inserts. After that the positions compare equal and ordering breaks silently, which is worse than breaking loudly.

Rejected

Client computes the new key

Chosen

Send neighbour IDs, server resolves in-transaction

Two clients looking at the same stale list compute the same midpoint, which puts the race straight back. Only the server sees the real neighbours at write time.

Rejected

Replace the whole list behind a version guard

Chosen

One row per move

Correct, and simpler. It also rejects any concurrent edit outright and makes the loser perform the drag a second time, which is a bad trade for a list several people touch in the same meeting.

Rejected

Rows shift out of the way under the cursor

Chosen

A static insertion line

Live shift only reads well with uniform-height rows. These are variable-height markdown, so a tall item displacing short ones makes the list jump and slides the drop target out from under the cursor. See it jump

Rejected

The full row follows the cursor

Chosen

A collapsed single-line proxy

A tall block under the cursor covers the list you are aiming at. The proxy only has to say which row is in your hand. See the full-row proxy

Presence

Rejected

A wash, a byline and a blinking caret

Chosen

One small avatar in the gutter

Three pieces of apparatus to say one fact: somebody is in this row. The avatar says it alone, and the row treatment says what they are doing to it. See the wash

Rejected

A presence strip with a count

Chosen

Presence on the row it belongs to

A header strip, a badge row and a "nobody is typing" line spend permanent space on a fact that is usually nothing. If presence needs saying, it gets said where it happened.

Rejected

The avatar beside the author tag

Chosen

Floating in the left gutter

The row already carries one avatar on the right. A second one next to it reads as co-authorship rather than presence. Off the corner it reads as somebody leaning over the row, and it costs the text no space.

Rejected

A 3s delay before the row settles

Chosen

1.5s, cancelled by any further typing

Autosave at 4s idle lands almost exactly on the pause somebody takes to think of a word, so tying the settle to the save event strobes the row. 3s stopped the strobing but read as too slow. At 1.5s, bursts separated by 3s pauses and by 5s pauses both produced zero transitions.

Rejected New

Dimming the row while the words move

Chosen

Open. Replacement is C3's job

Rejected on measurement, not taste. The dim is #1C1917 at opacity: .42 over white, which resolves to about #A09E9E and measures ~2.6:1 against the 4.5:1 that WCAG 1.4.3 asks for. It also fought the point of sending keystrokes at all, by greying text exactly while it changes. Two arguments had already been made against it; the number is what settled it. See the dim

Still shipped, still failing. Completed items render at opacity: .5, which measures about 3.2:1. That is the current treatment rather than a proposal, so it is a live finding rather than a rejected option, and it wants confirming against the real widget before anyone repeats it.
