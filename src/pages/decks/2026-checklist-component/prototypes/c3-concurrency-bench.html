What happens when two saves collide

Last save wins is what ships today. Merge is the same idea as a git merge: take what the editor started from, what they typed, and what is stored now, and combine all three. Where both people changed the same words it cannot choose, so it keeps both, which is the garbled text somebody then fixes.

The base is the whole trick. A merge needs three texts, not two: what the editor started from, what they typed, and what is stored now. The client already has the first one, because it loaded the text when editing began, so it can send "here is what I started from" along with the edit. That is what makes this cheaper than it sounds: no version column, no new transport, no merge engine on the client.

What this does not do. It merges at save time, not per keystroke. Two people typing for a minute diverge for a minute and then meet. Real character-level merging is the destination and it costs more: storing document state instead of a string, and a way for someone joining mid-edit to catch up. This is the same promise, implemented more crudely, and it comes out cleanly when the real thing lands.
