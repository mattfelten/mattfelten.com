What that did

Move a row, or tab into one.

The keyboard path was necessary and it was never sufficient. It arrived a round early, in nesting, and it covers a keyboard and a screen reader on a desktop. It does nothing at all for a touchscreen, which has neither hover to reveal the handle nor a keyboard to replace it. Turn on Simulate a touchscreen with Keyboard lift selected and there is no way to move a row at all.

Move up and Move down in the row menu is the one path that covers everybody, and it is also the smallest thing to build. It is a single pointer, so it satisfies 2.5.7 literally. It is a button, so the keyboard and the screen reader get it for nothing. The handle stays for people who like dragging, and it stops being the only way in.
